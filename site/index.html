Vendor-neutral · local models welcome · zero dependencies

An agent at every step. A human at every gate.

From a rough request to a tagged release and a production incident, one role-agent per step. Everything is a file in git, every step ends with a person deciding, and nothing reaches main except through a pull request.

How it fits together

Three layers. Only the thin one knows your vendor.

Roles, rules and artifacts are plain Markdown. The runner is a small script with no dependencies. Anything specific to a CI host or an AI product sits in a replaceable adapter.

1 · Content

AGENTS.md, CONTEXT.md, nine roles, skills, policies, templates, schemas and pipeline.yaml. Portable between any model or tool.

2 · Core

tools/agentrun.py builds the prompt, calls a model, keeps only allowed files, runs checks. validate and trace_check are plain scripts.

3 · Adapters

GitHub workflows, mise tasks, pointers for Claude Code, Copilot and Cursor. Swap them without touching layers 1 and 2.

When you are working

The developer loop.

Implement is the one stage where you and the agent alternate fast. One task, one commit, repeat until every box in tasks.md is ticked.

  1. Planimplement --plan shows what it would write
  2. Runmise run implement writes files, runs checks
  3. Readgit diff, every line
  4. Testyour project's suite; the runner does not
  5. Fixby hand, or split the task
  6. Commitfeat(US-002): task
  7. Repeatuntil tasks.md is all ticked

Then advance US-002 implemented, run Test and QA.

Your checklist

  • Be on feature/<US-id>-<slug>, never main
  • Read the whole diff before committing
  • Run the tests yourself
  • Answer open questions; do not let the agent guess
  • Bump status only after the artifact exists
  • Open the PR with a Conventional Commit title

Never

  • Let the agent "make tests pass" by editing tests
  • Loosen a schema or validator to get green
  • Commit or push directly to main
  • Name an AI assistant in a commit, PR or branch
  • Edit CHANGELOG.md, versions or tags
  • Paste secrets into stories, incidents or prompts
  • Merge on the strength of the agent's review alone
End to end

One story, from request to tag.

What actually happens for US-002, and who is acting at each moment.

  1. You Capture and branch

    mise run new "Export invoices as CSV" then mise run branch US-002. You are on feature/US-002-export-invoices-as-csv; status draft.

  2. Agent Story

    Analyst writes criteria, edge cases and open questions. Status becomes enriched.

  3. You Approve

    Answer questions, edit, advance US-002 approved, commit docs(US-002): approve story.

  4. Agent Spec, then design

    OpenSpec change, then design note and ADR. After each, you review and advance to specified, then designed.

  5. You + Agent Build

    The developer loop, one task per commit: feat(US-002): csv writer, feat(US-002): download endpoint. Then the test and QA stages; QA pass allows done.

  6. CI + Agent Pull request

    You open a PR titled feat(US-002): export invoices as CSV. CI checks the title, validates artifacts, checks traceability, runs tests. The reviewer agent comments.

  7. You Merge

    Fix blockers, squash-merge. One commit lands on main.

  8. release-please Release PR

    Sees a feat, opens chore(main): release 1.1.0 with the changelog.

  9. You Ship

    Merge the release PR. Tag v1.1.0 and the GitHub release are created.

The reviewer

One review of the whole PR. One comment, updated in place.

A review that only sees the latest push is useless, and a bot that adds a new comment every run is noise. The reviewer reads every commit of the PR against its real base branch and keeps a single comment current.

Whole PR by default

mise run review covers every commit against the PR's base branch plus your uncommitted changes. --commit reviews just the last commit and is never posted.

One comment, in place

--post and CI find their own marked comment and edit it. Never the "last comment", never a human's, never a second one.

Safe on failure

If listing comments fails, nothing is posted rather than a duplicate. One run per PR at a time; a newer push cancels the stale run.

CommandReviewsPosts
mise run reviewwhole PR vs its base (+ uncommitted)no
mise run review --postwhole PRone comment, updated in place
mise run review --commitlast commit onlynever
mise run review --post --commitrefused: a one-commit review must not replace the PR review

It is advice, not a gate: it can miss things and report things that are not there. You verify every finding.

Branches, commits, versions

PR mode, always. Trunk-based.

One long-lived branch. One short-lived branch per story. Conventional Commits drive SemVer through release-please.

Commit / PR titleEffect
feat(US-002): export invoices as CSVminor
fix(US-002): escape quotespatch
feat(US-002)!: drop legacy export or BREAKING CHANGE:major
docs test refactor perf build ci choreno release by themselves

Non-story work uses chore/<slug> or docs/<slug>. Incidents use fix/INC-001-<slug>.

Guard rails

Agents propose. Scripts check. People decide.

Writes are confined

Each stage may only write paths in its out list. Absolute paths and .. are discarded.

Inputs are data

Issues, logs and PR text are wrapped as untrusted data. Instructions inside them are ignored by policy.

Deterministic checks

Schema, sections, Given/When/Then, spec scenarios and the story-to-QA chain are checked by scripts, not opinions.

Humans own gates

Agents never merge, deploy, tag or touch production. The runner has no code path for it.

PR mode, always

No direct commits to main. Every change is a branch, a reviewed PR and a squash-merge.

Audit trail

Every applied run logs stage, provider, prompt hash, files written and check errors to .agents/runs/.

History stays human

A commit-msg hook and a CI scan reject assistant or tool names in commits, authors and PR text. No trailers, no banners.

No duplicate comments

One review comment per author, matched by a hidden marker and updated in place. A failed lookup posts nothing.

Unconfigured means skipped

Agent workflows check for a model and skip with a notice. CI stays green and deterministic checks always run.

What is not guarded: whether the content is right. That is what the gates are for.

Bring any model

Local, hosted or a CLI you already use.

Local server

Ollama, vLLM, llama.cpp, LM Studio

AGENT_PROVIDER=openai
AGENT_BASE_URL=http://localhost:11434/v1
AGENT_MODEL=gemma4:12b

Hosted API

Any OpenAI-compatible endpoint

AGENT_PROVIDER=openai
AGENT_BASE_URL=https://api.example/v1
AGENT_API_KEY=...
AGENT_MODEL_STRONG=...
AGENT_MODEL_CHEAP=...

Any CLI

Prompt on stdin, answer on stdout

AGENT_PROVIDER=cmd
AGENT_CMD="claude -p"
# or "codex exec -"
# or "ollama run llama3.1"

Stages ask for a cheap or strong tier. Put them in .env; mise run doctor checks the endpoint and that the model is served.

Quick start

mise trust && cp .env.example .env

Set AGENT_MODEL in .env.

mise run doctor

Python, git, endpoint, model served.

mise run branch US-002

Off main before any commit.

mise run story US-002 --dry
