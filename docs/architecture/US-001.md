## Overview
Stateless request/confirm endpoints backed by a `reset_tokens` table; email via the existing mailer.

## Components
- ResetService: issues and verifies tokens.
- RateLimiter: per account and per IP counters.
- Mailer: sends the link.

## Data and interfaces
- `reset_tokens(id, account_id, token_hash, expires_at, used_at)`
- `POST /password-reset/request`, `POST /password-reset/confirm`

## Risks
- Enumeration through timing: pad the unknown-email path.
- Token leakage in logs: never log full tokens.

## Test strategy
One test per spec scenario, plus a timing-parity test and a concurrency test on confirm.
